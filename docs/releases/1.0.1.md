# ViewSense AI® 1.0.1

This release packages the Kubernetes **evaluation reference** as downloadable Helm and offline
installation assets. It is suitable for synthetic integration testing and disposable environments.

- Architecture-specific Linux ARM64 and AMD64 bundles include the application, PostgreSQL and
  pgvector image archives, Helm chart, installer, checksums and documentation snapshot.
- The installer requires an explicit Kubernetes context and creates a new `viewsense-release-*`
  namespace with independent short-lived PKI, identity grants and database passwords.
- Installation runs a Helm smoke test covering authentication, memory, ingestion, tools,
  governance and durable agent state, followed by allowed/denied mTLS connectivity probes.
- Owned evaluation namespaces can be deleted and recreated without rotating development secrets.
- Packaging records paired application/documentation commits. Upload tooling creates a GitHub
  Release draft for operator review and explicit publication.

The full guide is included at `docs/releases/installation.md` in each extracted bundle.
Choose the bundle matching Kubernetes node architecture, verify `SHA256SUMS`, extract it,
and run `python3 install.py verify` before installation.

The reference uses mock inference/tools, deterministic embeddings, a development issuer,
static seven-day TLS leaves and single-replica databases. The management console and upstream
identity/model/mesh/observability products are separate. Production signing/provenance, renewable
identity, HA/backup/restore, ingress and full policy acceptance remain promotion work.

This baseline provides fresh installs and destructive evaluation resets. It does not claim a
data-preserving upgrade path or complete production security acceptance. Test evidence and
paired source commits accompany the reviewed release artifact.

Local validation: 100 unit/security/design tests, Ruff, all chart profiles, base Kustomize,
server-side Kubernetes manifest validation, strict documentation build and release-publishing
tests passed. The ARM64 reference ran in parallel blue/green namespaces on Kubernetes
`v1.31.5+k3s1`; green delete/recreate, end-to-end smoke and paired CNI/isolation probes passed
after local CNI controller recovery. This evidence does not certify the separate mesh profile,
production readiness or a native AMD64 cluster deployment.
