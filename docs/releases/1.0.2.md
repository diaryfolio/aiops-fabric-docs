# ViewSense AI® 1.0.2

This release packages the Kubernetes **evaluation reference**, with corrected GitHub draft
handling and an explicit manual release workflow. It retains architecture-specific offline
installers and a standalone Helm chart for synthetic testing and disposable environments.

- Release builds start only from **Actions → Release package → Run workflow**, using a version
  and the reviewed documentation commit. Pushes, merges and legacy trigger-file edits do not
  start packaging.
- Draft discovery uses the authenticated, paginated release list; verification uses the release
  ID. Completed releases are skipped and retries preserve existing tags and matching attachments.
- A prerequisite check verifies version-specific notes and clean source inputs before Docker
  setup, image builds or application tests.
- Downloads include `viewsense-1.0.2-linux-amd64.tar.gz`,
  `viewsense-1.0.2-linux-arm64.tar.gz`, `viewsense-1.0.2.tgz`, release notes and `SHA256SUMS`.
  GitHub's automatic source archives are separate from these installation assets.

Follow the [installation guide](installation.md) and
[parallel environment procedure](parallel-environments.md). Use new namespaces such as
`viewsense-release-1-0-2-blue` and `viewsense-release-1-0-2-green`, with independent credentials
and storage. Reset destroys the selected evaluation namespace's state. Production traffic
switching and state migration require an independently reviewed integration plan.

The reference uses mock inference/tools, deterministic embeddings, a development issuer,
short-lived static TLS material and single-replica databases. Real model products and the
host-side preview console remain separate from the offline installer. The container images
contain readable Python source; this release does not implement a compiled distribution,
registry publication, signed provenance, enterprise identity or a production upgrade path.

Publication and live Kubernetes acceptance of the 1.0.2 artifacts remain pending. Prior 1.0.1
ARM64 namespace evidence does not certify these new artifacts or a native AMD64 deployment.
The packager appends exact application/documentation commits to the generated release notes.
